Access modifiers

Look at the words public and private in the table above. They are access modifiers (keywords that decide which code may use a class or a member). You will see four of them in this guide.

public
Any code anywhere in the project can use this member.
Why use it. Other classes and forms need to reach it.
Where you use it. Properties, methods and constructors that a form calls.

private

Why use it. To protect data, so it can only change through rules the class controls.
Where you use it. Fields, and helper methods that only the class itself needs.
Exampleprivate decimal _balance; means only the account class can change the balance directly.

internal
Any code in the same project can use it, but code in other projects cannot. Visual Studio puts internal in front of a new class by default.
Why use it. Your classes are only used by your own app, so there is no need to open them to other projects.
Where you use it. The class header of every class you add with Project, Add Class.
Exampleinternal class Student can be used by every form in your project.
ExampleA different project in the same solution cannot see your internal classes.

Code in the same class and in its derived classes can use it. All other code is locked out.
Why use it. When a derived class needs direct access that outside code should not have.
Where you use it. Rarely in this module. You will see it mentioned again once you meet derived classes.
ExampleA protected method in Vehicle can be called inside Truck, but not from a form.
ExampleForm events use protected methods inside Windows Forms itself, which is why your form class can override some of them.

Inheritance and the Is-a Relationship

Textbook Section 10.1 · Pages 623 to 640

So what is inheritance, and why do you need it? You already know how to write a class with fields, properties, constructors and methods. Now think about two classes that are almost the same.

Picture a Student class with a student number, a name and a tuition fee. Now you need a class for students who live in residence. A resident student has everything a normal student has. They also have a residence name and a residence fee. You could copy the whole Student class and add two properties. But then the same code lives in two places. Fix a bug in one and you must remember to fix it in the other.

Inheritance solves this problem. You write the shared parts once, in one class. The new class takes them over and only adds what is different.

Inheritance
A way of creating a new class from an existing class. The new class automatically gets the public members of the existing class. Then it adds its own members on top.
Why use it. To write shared code once, so a fix in one place fixes every related class.
Where you use it. Whenever two or more classes in your project share most of their properties and methods, and one is a more specific kind of the other.
ExampleA ResidentStudent class inherits from Student. It gets the student number and name for free, and adds a residence name.
ExampleIn a taxi rank system, a Minibus class inherits from Vehicle. Every vehicle has a registration number. Only the minibus needs a seating capacity and a route.

The is-a test

How do you know when inheritance fits? Use the is-a test. Say the sentence "a ... is a ..." out loud. If it sounds true, inheritance fits. If it sounds wrong, it does not.

SentenceTrue?What to do
A resident student is a studentYesResidentStudent inherits from Student
A lecturer is a personYesLecturer inherits from Person
A car is an engineNoA car has an engine. Give Car an Engine property instead
A module is a lecturerNoA module has a lecturer. This is an association, not inheritance

The second kind of sentence is called a has-a relationship. You met it when you modelled association, aggregation and composition. A has-a relationship becomes a property. Only an is-a relationship becomes inheritance.

Quick Check
Which pair of classes passes the is-a test?
A permanent employee is an employee, so the sentence is true. A bicycle has wheels, a library has books, a student has marks, and a residence has rooms. Those are all has-a relationships.

Base Classes and Derived Classes

Textbook Section 10.1 · Pages 623 to 640

Now that you know when inheritance fits, you need the names for the two classes involved. Every inheritance relationship has a general class and a more specific class.

Base class
The general class that other classes inherit from. It holds the members that every related class shares. It is also called the parent class or superclass.
Why use it. It is the one place for everything the related classes have in common.
Where you use it. At the top of an is-a family. In your project, look for the general word, such as Person, Account, Vehicle or Booking.
ExampleStudent is the base class. Every student, resident or not, has a student number and a name.
ExampleAccount is the base class in a banking app. Savings accounts and cheque accounts both have an account number and a balance.
Derived class
The more specific class that inherits from a base class. It gets the base class members and adds its own. It is also called the child class or subclass.
Why use it. To add the extra data or behaviour that only one kind of object needs, without copying the base class.
Where you use it. Below a base class, for each specific kind, such as Lecturer under Person or SavingsAccount under Account.
ExampleResidentStudent is a derived class. It adds a residence name and a residence fee.
ExampleSavingsAccount is a derived class of Account. It adds an interest rate that a cheque account does not have.

Declaring a Derived Class in C#

Textbook Section 10.1 · Pages 623 to 640

Right, so how do you actually write a derived class in C#? You write a normal class header, then add a colon and the name of the base class. You read that colon as "inherits from".

C# · Vehicle.cs (the base class)
internal class Vehicle
{
    // Every vehicle has these two properties.
    public string Registration { get; set; } = "";
    public string Make { get; set; } = "";
}
C# · Truck.cs (the derived class)
// The colon means: Truck inherits from Vehicle.
internal class Truck : Vehicle
{
    // Only the NEW property goes here.
    // Registration and Make come from Vehicle automatically.
    public decimal LoadCapacity { get; set; }
}

Now look at the code that uses the class. This code sits on a form, in a separate file from the class declarations.

C# · Code on the form that uses Truck
Truck delivery = new Truck();
delivery.Registration = "EC 123-456";   // inherited from Vehicle
delivery.Make = "Isuzu";                // inherited from Vehicle
delivery.LoadCapacity = 8.5m;           // declared in Truck itself

Notice that Truck never declares Registration or Make. The delivery object still has them, because a truck is a vehicle.

Private fields stay private

Suppose Vehicle used a full property with a private field called _make. Code inside Truck cannot write _make = "Isuzu". The compiler says the field is inaccessible due to its protection level. Truck must go through the public Make property, like everyone else.

Keep Fields Private, Even with Inheritance

You met protected with the other access modifiers. It would let Truck touch the field directly. In this module, keep fields private and let derived classes use the public properties. That keeps the base class in control of its own data.

One Class, One File

Keep the same rule you use for every class in this module. Vehicle goes in Vehicle.cs and Truck goes in Truck.cs. Add each one with Project, Add Class.

Quick Check
Which class header correctly declares Lecturer as a derived class of Person?
The derived class comes first, then a colon, then the base class. Option a is the wrong way round. Option b uses the Java keyword extends, which C# does not have.

Constructors in Inheritance

Textbook Section 10.1 · Pages 623 to 640

You know constructors are not inherited. So how does a derived object get its base class values set up? Let us look at what happens when you create a derived object.

When you write new Truck(...), C# builds one object. That object has a Vehicle part and a Truck part. C# sets up the Vehicle part first. So the base class constructor always runs first. Then the derived class constructor runs.

Passing values to the base constructor

Now give Vehicle a parameterised constructor. The truck constructor must hand the registration and make up to it. You do this with the keyword base, placed after a colon at the end of the constructor header.

C# · Vehicle.cs with a constructor
internal class Vehicle
{
    public string Registration { get; }
    public string Make { get; }

    // Base class constructor. It sets up the shared values.
    public Vehicle(string registration, string make)
    {
        Registration = registration;
        Make = make;
    }
}
C# · Truck.cs with a constructor
internal class Truck : Vehicle
{
    public decimal LoadCapacity { get; }

    // ": base(registration, make)" sends those two values
    // to the Vehicle constructor, which runs FIRST.
    public Truck(string registration, string make, decimal loadCapacity)
        : base(registration, make)
    {
        // This body runs SECOND. It only sets up the Truck part.
        LoadCapacity = loadCapacity;
    }
}
C# · Code on the form
Truck delivery = new Truck("EC 123-456", "Isuzu", 8.5m);

Follow the values. "EC 123-456" and "Isuzu" travel through the Truck constructor's parameters. Then base(registration, make) passes them up to Vehicle. The value 8.5m stays in Truck.

Forget base and Your Code Will Not Compile

If the base class only has a parameterised constructor, the derived constructor must call it with : base(...). If you leave it out, C# tries to call a parameterless Vehicle constructor. There is none, so you get an error saying no argument matches the required parameter.

Assessed Content

This is assessed. You will be asked to write the constructor header of a derived class, including the call to the base constructor, or to state which constructor runs first.

Example question

The base class Person has the constructor public Person(string name). Write only the constructor header for a derived class Lecturer that receives a name and an office number (int), and passes the name to the base constructor. (2)

How to prepare

  • Learn the pattern. Derived constructor parameters, then : base( the values the base needs ).
  • The base constructor runs first, the derived constructor runs second.
  • Practise writing three derived constructors of your own, each with a different base class.

Method Overriding with virtual and override

Textbook Section 10.2 · Pages 641 to 650

Sometimes a derived class needs a method to behave differently from the base class version. That is what method overriding is for.

Method overriding
Writing a new version of an inherited method inside the derived class. The new version has the same name, the same return type and the same parameters. It replaces the base version for objects of the derived class.
Why use it. The derived class does the same job as the base class, but in a different way.
Where you use it. Calculations that change by type, such as fees, pay or prices, and the text a class shows in a ListBox.
ExampleEvery vehicle pays a licence fee. A truck's fee also depends on its load capacity, so Truck overrides the fee calculation.
ExampleEvery student has total fees. A resident student's total also includes the residence fee, so ResidentStudent overrides the total.

C# needs permission from both sides before overriding works.

  • The base class marks the method virtual. This says "derived classes are allowed to replace me".
  • The derived class marks its version override. This says "I am replacing the base version on purpose".
C# · Vehicle.cs with a virtual method
internal class Vehicle
{
    // ... properties and constructor as before ...

    // virtual: derived classes MAY replace this method.
    public virtual decimal CalculateLicenceFee()
    {
        return 450m;
    }
}
C# · Truck.cs with an override
internal class Truck : Vehicle
{
    // ... property and constructor as before ...

    // override: this version replaces the Vehicle version for trucks.
    public override decimal CalculateLicenceFee()
    {
        // base.CalculateLicenceFee() runs the Vehicle version (450).
        // Then we add R120 for every ton the truck can carry.
        return base.CalculateLicenceFee() + LoadCapacity * 120m;
    }
}

The line base.CalculateLicenceFee() is worth a closer look. The word base lets the derived class call the original version. So you reuse the base calculation instead of typing 450m again. A truck that carries 8.5 tons pays 450 plus 1020, which is R1 470.

KeywordWhere you write itWhat it means
virtualBase class method headerThis method may be replaced
overrideDerived class method headerThis method replaces the base version
base.Method()Inside the derived class method bodyRun the base version of this method
Quick Check
A developer writes public override decimal CalculateLicenceFee() in Truck. In Vehicle, the method header is public decimal CalculateLicenceFee(). What happens?
You can only override a method that the base class marked virtual (or abstract, which comes later). Without permission from the base class, the compiler rejects override.

Polymorphism

Textbook Section 10.2 · Pages 641 to 650

Now that you can override methods, you are ready for polymorphism. This is the idea that makes inheritance really powerful.

Polymorphism
The word means "many forms". In C#, it means a base class variable can hold an object of any derived class. When you call an overridden method through that variable, the version that runs belongs to the actual object.
Why use it. One piece of code can work with many kinds of objects, without an if statement for each kind.
Where you use it. A List of the base class that holds different derived objects, and a loop that processes them all.
ExampleA Vehicle variable holds a Truck object. Calling CalculateLicenceFee() runs the Truck version.
ExampleA list of students holds Sipho, a normal student, and Intelligence, a resident student. One loop calculates both totals correctly, because each object uses its own version.

A base variable can hold a derived object

Because a truck is a vehicle, C# lets you do this.

C# · Code on the form
// The variable type is Vehicle, but the object is a Truck.
Vehicle v = new Truck("EC 123-456", "Isuzu", 8.5m);

// Which version runs? The OBJECT decides, not the variable.
// The object is a Truck, so the Truck version runs.
decimal fee = v.CalculateLicenceFee();   // 1470

Keep these three rules in mind. They come up often.

  • The object decides which overridden method runs, not the type of the variable.
  • It only works one way. Truck t = new Vehicle(...) does not compile. A truck is a vehicle, but a vehicle is not always a truck.
  • The variable decides what you can see. Through a Vehicle variable, you cannot use v.LoadCapacity. Vehicle has no such property, even though the object does.

Why this is useful

Look at this loop. One list holds different kinds of vehicles. One line of code calculates every fee correctly. You never write an if statement to check what kind of vehicle you have.

C# · One loop, many forms
List<Vehicle> fleet = new List<Vehicle>();
fleet.Add(new Vehicle("EC 555-111", "Toyota"));           // a normal vehicle
fleet.Add(new Truck("EC 123-456", "Isuzu", 8.5m));        // a truck

decimal totalFees = 0m;
foreach (Vehicle item in fleet)
{
    // Vehicle version for the Toyota (450),
    // Truck version for the Isuzu (1470).
    totalFees += item.CalculateLicenceFee();
}
// totalFees is now 1920

Two pieces of this code may be new to you.

  • List<Vehicle> is a List, a collection that grows as you add items, unlike an array with a fixed size. The type inside the angle brackets says what it holds. Add puts a new item at the end.
  • foreach (Vehicle item in fleet) is a loop that visits every item in the list once, from first to last. Each time round, item refers to the current item.
Forget override and the Wrong Version Runs

If Truck writes public decimal CalculateLicenceFee() without override, the code still compiles with a warning. But the Truck method now hides the base method instead of replacing it. Through a Vehicle variable, the Vehicle version runs. The truck pays only R450 and nobody notices. Always write override.

Assessed Content

This is assessed. You will be shown a short piece of code with a base variable holding a derived object, and asked what a method call returns.

Example question

Shape has public virtual string Describe() { return "Shape"; } and Circle overrides it to return "Circle". After Shape s = new Circle();, what does s.Describe() return? a) Shape b) Circle c) ShapeCircle d) Nothing e) A compiler error. (1)

How to prepare

  • Find the line with new. That tells you the real object type.
  • Check whether the method is virtual in the base and override in the derived class. If both are there, the derived version runs.
  • Practise tracing the fleet loop above by hand, then change the values and trace it again.

Overriding the ToString Method

Textbook Section 10.2 · Pages 641 to 650

Here is a practical use of overriding that you will use in your project. It is overriding the ToString method.

Every class in C# inherits from one class at the very top, called object. You never write : object. C# adds it for you. The object class has a virtual method called ToString, so every object you create has one.

Now try this. Add a Vehicle object straight into a ListBox with vehiclesListBox.Items.Add(v). The ListBox calls ToString to decide what text to show. The default version only returns the class name, so you see something like FleetManager.Vehicle. That is useless to a user.

Override ToString and the ListBox shows your own text instead.

C# · Add this method to Vehicle.cs
// ToString is virtual in the object class, so we may override it.
public override string ToString()
{
    return Registration + " (" + Make + ")";
}

Now vehiclesListBox.Items.Add(v) shows EC 123-456 (Isuzu). The object itself is still in the ListBox. So when the user selects a line, SelectedItem gives you back the whole object, not just the text.

Quick Check
A Book class does not override ToString. A developer adds a Book object to a ListBox. What does the ListBox show?
The ListBox calls ToString. Book has not overridden it, so the version inherited from object runs. That version returns the full class name.

Abstract Classes and Abstract Methods

Textbook Section 10.3 · Pages 651 to 657

Let us move on to abstract classes. Some base classes describe an idea that is too general to exist on its own. Think about a university payroll. Every staff member gets paid. But a permanent staff member is paid a monthly share of an annual salary. A contract staff member is paid for the hours they work. There is no such thing as a staff member who is "just staff". So it makes no sense to create a plain staff object.

Abstract class
A class marked with the keyword abstract. You cannot create objects from it. It exists only so that other classes can inherit from it.
Why use it. To stop anyone creating an object that is too general to make sense, while still sharing code.
Where you use it. As the base class when every real object is always one of the specific kinds.
ExampleStaffMember is abstract. You create PermanentStaff and ContractStaff objects, never a plain staff member.
ExampleShape is abstract in a drawing app. You draw circles and rectangles. Nobody draws "a shape".
Abstract method
A method with a header but no body. It ends with a semicolon instead of curly brackets. Every derived class must override it and supply the body.
Why use it. To force every derived class to provide its own version, because there is no sensible default.
Where you use it. Inside an abstract class, for the job that each kind does completely differently.
ExampleCalculateMonthlyPay() is abstract in StaffMember. Each kind of staff member works it out in its own way.
ExampleCalculateArea() is abstract in Shape. A circle and a rectangle use different formulas.
C# · StaffMember.cs (abstract base class)
internal abstract class StaffMember
{
    public string Name { get; }

    public StaffMember(string name)
    {
        Name = name;
    }

    // No body. Every derived class MUST override this.
    public abstract decimal CalculateMonthlyPay();
}
C# · PermanentStaff.cs and ContractStaff.cs
internal class PermanentStaff : StaffMember
{
    public decimal AnnualSalary { get; }

    public PermanentStaff(string name, decimal annualSalary) : base(name)
    {
        AnnualSalary = annualSalary;
    }

    // Supplies the missing body.
    public override decimal CalculateMonthlyPay()
    {
        return AnnualSalary / 12;
    }
}

internal class ContractStaff : StaffMember
{
    public decimal HoursWorked { get; set; }
    public decimal HourlyRate { get; }

    public ContractStaff(string name, decimal hourlyRate) : base(name)
    {
        HourlyRate = hourlyRate;
    }

    public override decimal CalculateMonthlyPay()
    {
        return HoursWorked * HourlyRate;
    }
}

The two classes are shown together here to save space. In your project, each one goes in its own file.

C# · Code on the form
StaffMember s = new StaffMember("Thandi");          // ERROR. Abstract classes cannot be created.
StaffMember p = new PermanentStaff("Thandi", 360000m);   // fine
decimal pay = p.CalculateMonthlyPay();              // 30000

C# · Student.cs
internal class Student
{
    // Read-only auto-properties. They are set once, in the constructor.
    public string StudentNumber { get; }
    public string Name { get; }
    public decimal TuitionFee { get; }

    public Student(string studentNumber, string name, decimal tuitionFee)
    {
        StudentNumber = studentNumber;
        Name = name;
        TuitionFee = tuitionFee;
    }

    // virtual: derived classes may replace this calculation.
    public virtual decimal CalculateTotalFees()
    {
        return TuitionFee;
    }

    // virtual: derived classes may add to this summary.
    public virtual string GetSummary()
    {
        // This calls CalculateTotalFees(). If the object is a
        // ResidentStudent, the OVERRIDDEN version runs here.
        return Name + " (" + StudentNumber + ") owes R" +
               CalculateTotalFees().ToString("N2");
    }
}

Step 4 · Add the derived class

  1. Click Project, then Add Class again.
  2. Name the file ResidentStudent.cs and click Add.
  3. Replace the empty class with this code.
C# · ResidentStudent.cs
// ResidentStudent inherits from Student.
internal class ResidentStudent : Student
{
    // Only the NEW members are declared here.
    public string ResidenceName { get; }
    public decimal ResidenceFee { get; }

    // The first three values go up to the Student constructor,
    // which runs first. The last two stay here.
    public ResidentStudent(string studentNumber, string name, decimal tuitionFee,
                           string residenceName, decimal residenceFee)
        : base(studentNumber, name, tuitionFee)
    {
        ResidenceName = residenceName;
        ResidenceFee = residenceFee;
    }

    // Replaces the Student version. Reuses it with base, then adds residence.
    public override decimal CalculateTotalFees()
    {
        return base.CalculateTotalFees() + ResidenceFee;
    }

    // Reuses the Student summary and adds the residence name to the end.
    public override string GetSummary()
    {
        return base.GetSummary() + ", lives in " + ResidenceName;
    }
}

public partial class Form1 : Form

    {

        students.Clear();

        students.Add(sipho);
        students.Add(intelligence);

        decimal grandTotal = 0m;

        // Polymorphism. Each object runs its OWN version of
        // GetSummary() and CalculateTotalFees().
        foreach (Student s in students)
        {
            studentsListBox.Items.Add(s.GetSummary());
            grandTotal += s.CalculateTotalFees();
        }

        totalLabel.Text = "Total owed by all students: R" + grandTotal.ToString("N2");
    }

    private void exitButton_Click(object sender, EventArgs e)
    {
        this.Close();
    }

Why Applications Need a Database

Textbook Section 11.1 · Pages 663 to 665

So why do applications need a database at all? Think about every app you have built so far. You type in students, marks or stock items. Then you close the app and open it again. Everything is gone.

That happens because your data lives in memory (the computer's short term working space, called RAM). Variables, arrays, Lists and objects all live in memory. The moment the program stops, the computer wipes that memory clean.

Why not just use a text file?

You could write data to a text file and read it back next time. That works for a tiny app. But it breaks down quickly in a real system.

  • Searching is slow. To find one student in a file, the program must read through the whole file line by line.
  • Nothing checks the data. A file will happily store a blank name or the word "abc" as a price.
  • Sharing is risky. If two people save to the same file at the same time, one person's changes can be lost.
  • Linking data is hard. Connecting each loan to the right book, across two files, is a lot of code.

A database solves all four problems. That is why almost every business system, from the university's student system to a bank app, keeps its data in a database.

Quick Check
A student builds an app that stores marks in a List<int>. The marks are gone every time the app restarts. Why?
Anything in memory only lasts while the program runs. To keep data, you must store it permanently, in a file or a database.

What a Database Is

Textbook Sections 11.1 and 11.2 · Pages 663 to 667

Now that you know why you need one, let us define exactly what a database is, and the software that runs it.

Database
An organised collection of data that is stored permanently, so you can add to it, change it and search it later.
Why use it. To keep data safe, organised and searchable after the app closes.
Where you use it. Any app that must remember something, such as stock, bookings, marks or users.
ExampleThe university keeps every student's registration and marks in a database. The data is still there next year.
ExampleA spaza shop app records every sale in a database. At month end the owner can see which items sold the most.
Database management system (DBMS)
The software that stores the database and lets programs work with it. Your app never touches the data files directly. It asks the DBMS, and the DBMS does the work.
Why use it. The DBMS handles searching, checking rules, and many users at once, so your code does not have to.
Where you use it. In this guide, the DBMS is SQL Server Express LocalDB.
ExampleWhen your app asks for all items under R13, the DBMS finds them and sends them back.
ExampleOther well-known DBMSs are MySQL, Oracle and SQLite. Many banking and retail systems in South Africa run on them.
Relational database
A database that stores data in tables, and links the tables to each other through shared values. SQL Server is a relational DBMS.
ExampleA library database has a Books table and a Loans table. Each loan row holds the number of the book it belongs to.
ExampleA clinic database links an Appointments table to a Students table through the student number.

Think of the DBMS as the librarian and the database as the books on the shelves. You never walk into the storeroom yourself. You ask the librarian, and the librarian fetches or files what you need.

Primary Keys

Textbook Sections 11.2 and 11.3 · Pages 665 to 676

Every table needs a way to tell its rows apart. Imagine two stock items with the same price and quantity. If you ask the database to change "the one costing R10", which row should it change? A primary key removes that confusion.

Primary key
A column whose value is different for every row, and is never empty. It identifies exactly one row.
Why use it. So that every update, delete and link can point at exactly one row, with no mix ups.
Where you use it. Every table you create. Usually it is the first column.
ExampleYour student number is the primary key in the university's student table. Two students may both be called Sipho, but their student numbers are different.
ExampleIn the Stock table, ItemId is the primary key. Two items could cost the same, but they never share an ItemId.

The two rules of a primary key

  1. Unique. No two rows may share the same value. The DBMS refuses a second row with an ItemId that already exists.
  2. Never empty. Every row must have a value. The DBMS refuses a row with no ItemId.

Letting the DBMS create the number

Often there is no natural unique value, such as a student number. Then you let the DBMS make one. In SQL Server, IDENTITY(1,1) means "start at 1 and add 1 for every new row". You never type that value yourself.

One thing surprises students. If you delete row 7, the next new row gets 8, not 7. An identity number is never reused, so an old reference can never point at the wrong row by mistake.

Foreign key
A column in one table that holds the primary key value of a row in another table. It is the link between the two tables.
Why use it. To connect related data without repeating it, and so the DBMS can check that every link points to a row that really exists.
Where you use it. In the table on the "many" side of a relationship, such as Loans.
ExampleBookId in the Loans table is a foreign key. It points to BookId in the Books table.

One to many relationship
One row in the first table can be linked to many rows in the second table, but each row in the second table links back to only one.
ExampleOne book can have many loans over time. Each loan is for exactly one book.
ExampleOne lecturer teaches many modules. Each module has one lecturer in charge.

The standard language for working with relational databases. You use it to create tables, and to read, add, change and delete data.
Why use it. Every relational DBMS understands it, so the same skill works in SQL Server, MySQL and Oracle.

Almost every business app does four jobs with its data. Together they are called CRUD. Each job has its own SQL statement.

Reading Data with SELECT

Textbook Section 11.7 · Pages 706 to 712

Let us start with the R in CRUD, reading data. The statement that reads data is SELECT. It never changes anything. It only gives you a copy of what you ask for.

The basic shape

SQL · Basic SELECT
SELECT ItemName, Price      -- which columns you want
FROM Stock;                 -- which table they come from

Use * instead of column names to get every column. SELECT * FROM Stock returns the whole table.

Filtering rows with WHERE

WHERE keeps only the rows that match a condition. Everything else is left out.

SQL · WHERE examples
SELECT * FROM Stock WHERE Price < 13;                    -- cheaper than R13
SELECT * FROM Stock WHERE Quantity = 0;                   -- out of stock
SELECT * FROM Stock WHERE ItemName = 'Bar-One 55g';       -- text goes in single quotes
SELECT * FROM Stock WHERE Price < 13 AND Quantity > 20;  -- both must be true
SELECT * FROM Stock WHERE Price < 13 OR Quantity = 0;    -- either one may be true
OperatorMeaning
=Equal to
<>Not equal to
< > <= >=Less than, greater than, and the "or equal to" versions
AND, ORCombine two conditions

Searching for part of a word with LIKE

LIKE matches a pattern. The % sign stands for "any characters, or none".

SQL · LIKE examples
SELECT * FROM Stock WHERE ItemName LIKE 'Simba%';   -- starts with Simba
SELECT * FROM Stock WHERE ItemName LIKE '%55g';     -- ends with 55g
SELECT * FROM Stock WHERE ItemName LIKE '%cola%';   -- contains cola anywhere

Sorting with ORDER BY

SQL · ORDER BY
SELECT * FROM Stock ORDER BY Price;           -- cheapest first (ASC is the default)
SELECT * FROM Stock ORDER BY Price DESC;      -- most expensive first

Counting rows

SQL · COUNT
SELECT COUNT(*) FROM Stock WHERE Quantity < 10;   -- how many items are running low

This returns one single number, not a list of rows. Keep that in mind, because it changes which C# method you use later.

The Clauses Always Go in This Order

SELECT, then FROM, then WHERE, then ORDER BY. Putting ORDER BY before WHERE is a syntax error.

Changing Data with INSERT, UPDATE and DELETE

Textbook Section 11.7 · Pages 706 to 712

SELECT only reads. The other three CRUD statements change the data. Let us go through them one at a time.

INSERT adds a new row (Create)

SQL · INSERT
INSERT INTO Stock (ItemName, Price, Quantity)   -- the columns you are filling
VALUES ('Fanta Orange 330ml', 14.50, 30);       -- the values, in the same order

Notice that ItemId is missing. It is an IDENTITY column, so SQL Server fills it in. If you list a column, you must give a value for it in the same position.

UPDATE changes existing rows (Update)

SQL · UPDATE
UPDATE Stock                          -- which table
SET Price = 13.49, Quantity = 45      -- which columns get which new values
WHERE ItemId = 1;                     -- which row or rows

DELETE removes rows (Delete)

SQL · DELETE
DELETE FROM Stock      -- which table
WHERE ItemId = 3;      -- which row or rows
Never Forget the WHERE

UPDATE Stock SET Price = 0 sets every price in the table to zero. DELETE FROM Stock deletes every item. Both run without any warning. Always write the WHERE clause first, and use the primary key in it, so you change exactly one row.

DELETEAlmost alwaysDeletes every row in the table

The word using, in two different jobs

You will see using in two places in database code. They do different jobs, so do not mix them up.

  • A using directive sits at the very top of a file, such as using Microsoft.Data.SqlClient;. It tells C# where to find class names, so you can write SqlConnection instead of the long full name.
  • A using statement sits inside a method, with brackets, such as using (SqlConnection connection = ...). It closes and cleans up the object at the closing curly bracket, even if an error happens inside. A database connection is a limited resource, so this matters.
C# · Reading rows with a SqlDataReader
List<string> titles = new List<string>();
string sql = "SELECT Title FROM Books ORDER BY Title";

using (SqlConnection connection = new SqlConnection(connectionString))
using (SqlCommand command = new SqlCommand(sql, connection))
{
    connection.Open();                       // a reader needs an open connection
    using (SqlDataReader reader = command.ExecuteReader())
    {
        while (reader.Read())                // Read() moves to the next row
        {
            titles.Add(reader["Title"].ToString());
        }
    }
}   // the connection closes here automatically

using System.Data;                 // DataTable lives here
using Microsoft.Data.SqlClient;    // SqlConnection, SqlDataAdapter and friends

// The data tier class. The form never writes SQL, it calls these methods.
internal class StockData
{
    // const means this value is fixed and can never change while the app runs.
    // @ in front of the string means the backslash is a normal character.
    private const string ConnectionString =
        @"Server=(localdb)\MSSQLLocalDB;Database=TuckShopDB;" +
        "Integrated Security=True;TrustServerCertificate=True;";

    // The same SELECT is used for loading and for saving.
    private const string SelectSql =
        "SELECT ItemId, ItemName, Price, Quantity FROM Stock";

    // Reads every row of the Stock table into a DataTable.
    public DataTable LoadStock()
    {
        DataTable table = new DataTable();

        using (SqlConnection connection = new SqlConnection(ConnectionString))
        using (SqlDataAdapter adapter = new SqlDataAdapter(SelectSql, connection))
        {
            // Fill opens the connection, runs the SELECT,
            // copies the rows into the table, then closes the connection.
            adapter.Fill(table);
        }

        return table;
    }

    // Sends every added, changed or deleted row back to the database.
    // Returns how many rows were saved.
    public int SaveStock(DataTable table)
    {
        using (SqlConnection connection = new SqlConnection(ConnectionString))
        using (SqlDataAdapter adapter = new SqlDataAdapter(SelectSql, connection))
        using (SqlCommandBuilder builder = new SqlCommandBuilder(adapter))
        {
            // The command builder reads the SELECT and writes the matching
            // INSERT, UPDATE and DELETE statements for you.
            return adapter.Update(table);
        }
    }
}

How saving works

This part surprises most students, so take it slowly. The DataTable is a copy in memory. When the user edits the grid, only the copy changes. The database stays the same until you call SaveStock.

The DataTable remembers what happened to every row. It marks each row as added, changed, deleted or unchanged. adapter.Update(table) walks through those marks. It runs an INSERT for each added row, an UPDATE for each changed row and a DELETE for each deleted row. So all of CRUD happens through one method.

The Command Builder Needs a Primary Key

SqlCommandBuilder uses the primary key to know which row to update or delete. That is why ItemId must be in the SELECT. Leave it out and saving fails.

Now let us write the data tier class for the library. The new idea in this class is the parameter. It is how you put the user's search text into SQL safely.

Parameter (in SQL)
A named placeholder in a SQL statement, written with an @ sign. Your C# code supplies the value separately. The database always treats that value as data, never as part of the SQL command.
Why use it. To put anything the user typed into SQL safely.

Step 4 · Add the BookData class

Add a class file called BookData.cs, add the two using directives at the top, and replace the empty class.

C# · BookData.cs
using System.Data;
using Microsoft.Data.SqlClient;

internal class BookData
{
    private const string ConnectionString =
        @"Server=(localdb)\MSSQLLocalDB;Database=LibraryDB;" +
        "Integrated Security=True;TrustServerCertificate=True;";

    // Every query returns the same columns, so the form controls always match.
    private const string SelectBooks =
        "SELECT BookId, Title, Author, YearPublished, IsOnLoan FROM Books ";

    // All books, sorted by title.
    public DataTable GetAllBooks()
    {
        DataTable table = new DataTable();
        string sql = SelectBooks + "ORDER BY Title";

        using (SqlConnection connection = new SqlConnection(ConnectionString))
        using (SqlDataAdapter adapter = new SqlDataAdapter(sql, connection))
        {
            adapter.Fill(table);
        }
        return table;
    }

    // Only the books whose title or author contains the search text.
    public DataTable SearchBooks(string searchText)
    {
        DataTable table = new DataTable();
        string sql = SelectBooks +
                     "WHERE Title LIKE @search OR Author LIKE @search ORDER BY Title";

        using (SqlConnection connection = new SqlConnection(ConnectionString))
        using (SqlCommand command = new SqlCommand(sql, connection))
        using (SqlDataAdapter adapter = new SqlDataAdapter(command))
        {
            // The value goes in separately. The % signs mean "contains".
            command.Parameters.AddWithValue("@search", "%" + searchText + "%");
            adapter.Fill(table);
        }
        return table;
    }

    // One single number, so we use ExecuteScalar.
    public int CountBooksOnLoan()
    {
        string sql = "SELECT COUNT(*) FROM Books WHERE IsOnLoan = 1";

        using (SqlConnection connection = new SqlConnection(ConnectionString))
        using (SqlCommand command = new SqlCommand(sql, connection))
        {
            connection.Open();   // ExecuteScalar needs an open connection
            return (int)command.ExecuteScalar();
        }
    }
}

Reading the new code

  • SearchBooks builds a SqlCommand first, so it can attach a parameter. Then it hands the command to the adapter.
  • AddWithValue("@search", ...) links the placeholder to the real value. If the user types mda, the value becomes %mda%.
  • CountBooksOnLoan uses ExecuteScalar, because COUNT returns one number.
  • ExecuteScalar gives back a value of type object, which can hold anything. The (int) in front is a cast (an instruction to treat a value as a specific type). It turns the object into a whole number.
  • Unlike Fill, ExecuteScalar does not open the connection for you. That is why you see connection.Open().
Never Glue User Text Into SQL

Writing "WHERE Title LIKE '%" + searchTextBox.Text + "%'" looks easier. Do not do it. A user can type SQL into the search box and change what your command does. Parameters stop this. You will see the full reason in Part 3.

But what happens when he types letters in the price box, leaves the name empty, or the database is switched off? A system with integrity keeps working correctly in all of those cases.

Robustness and Defensive Programming

New Addition

Let us start with robustness. A robust app is hard to break. Users cannot crash it by typing the wrong thing, and it survives problems such as a missing file or a database that is down.

Robustness
The ability of a program to keep running and respond sensibly when it receives unexpected input or when something it depends on fails.
ExampleA marks app receives a blank mark. It asks for the mark again instead of crashing.
ExampleA library app cannot reach its database. It explains the problem and keeps the form open, so the user can try again.
Defensive programming
A way of writing code that assumes input and outside resources might be wrong, and checks them before using them.
ExampleUsing int.TryParse instead of int.Parse, because the text box might not hold a number.
ExampleChecking that a ListBox has a selected item before reading SelectedItem.

Fragile code next to robust code

C# · Fragile, crashes on bad input
// If the box holds "abc" or is empty, this line throws an exception
// and the whole app can stop.
int quantity = int.Parse(quantityTextBox.Text);
C# · Robust, handles bad input
int quantity;
if (!int.TryParse(quantityTextBox.Text, out quantity))
{
    MessageBox.Show("Quantity must be a whole number.");
    quantityTextBox.Focus();   // put the cursor where the problem is
    return;                    // stop here, do not use a bad value
}

The rules of defensive programming

  1. Never trust input. Every value from a user, a file or a database could be wrong.
  2. Check before you use. Validate a value before you calculate with it or save it.
  3. Handle what can fail. Wrap database and file work in try and catch, because those can fail for reasons your code cannot control.
  4. Fail gracefully. When something goes wrong, show a clear message, keep the app running, and leave the data unchanged.
  5. Guide the user back. Put the focus on the control that needs fixing, so the user knows exactly where to look.
Quick Check

Failing gracefully means the user understands what happened, the app stays usable, and the data stays correct. Hiding errors is not graceful, it just makes them harder to find.

Checking that input is sensible and allowed before the program uses it or stores it. Validation cannot prove a value is true. It can only prove a value is acceptable.
ExampleA mark of 75 passes validation. Validation cannot tell if the real mark was 57 and the user swapped the digits.

Exception Handling with try, catch and finally

New Addition

Validation stops the problems you can predict. Exception handling deals with the problems you cannot predict, or cannot check for in advance.

Exception
An error that happens while the program is running. If nothing handles it, the program stops at that line.
Exampleint.Parse("abc") throws a FormatException.
ExampleOpening a connection to a database that is offline throws a SqlException.

The three blocks

  • try holds the code that might fail.
  • catch runs only if an exception happens in the try block. You can have several, one per type of exception.
  • finally runs every time, whether an exception happened or not. Use it for clean up work that must always happen.
C# · Several catch blocks and a finally block
calculateButton.Enabled = false;   // stop double clicks while we work
try
{
    decimal total = decimal.Parse(totalTextBox.Text);
    int people = int.Parse(peopleTextBox.Text);
    decimal share = total / people;          // fails if people is 0
    shareLabel.Text = "Each person pays R" + share.ToString("N2");
}
catch (FormatException)
{
    MessageBox.Show("Please type numbers only.");
}
catch (DivideByZeroException)
{
    MessageBox.Show("The number of people cannot be zero.");
}
catch (Exception ex)
{
    // The general catch goes LAST. It handles anything not caught above.
    MessageBox.Show("Something unexpected went wrong. " + ex.Message);
}
finally
{
    // Runs whether the calculation worked or failed.
    calculateButton.Enabled = true;
}

Common exception types

ExceptionWhen it happens

OverflowExceptionA number is too big for its type

Three rules for good exception handling

  1. Specific catch blocks first, general last. If catch (Exception) comes first, it catches everything. The compiler then refuses the specific catch blocks below it.
  2. Never leave a catch block empty. An empty catch hides the error. The app looks fine, but the work was never done.
  3. Do not use exceptions instead of validation. A user typing letters is predictable, so check it with TryParse. Save try and catch for things outside your control, such as databases and files.

Data Integrity and SQL Injection

New Addition

Validation protects your form. Data integrity protects what is stored. Let us look at the rules a database uses to keep its data correct, and at one attack that can destroy it.

Data integrity
The accuracy, completeness and consistency of stored data over its whole life. Data with integrity can be trusted.
ExampleEvery stock item has a name and a price, and no two items share an ItemId.
ExampleA loan record always points to a book that really exists in the Books table.

Three kinds of data integrity

KindWhat it protectsHow SQL Server enforces it
Entity integrityEvery row can be identifiedPRIMARY KEY
Domain integrityEvery value is the right type and within allowed limitsData types, NOT NULL, CHECK, DEFAULT
Referential integrityLinks between tables always point to rows that existFOREIGN KEY

You met primary keys, NOT NULL, DEFAULT and foreign keys in Part 2. Now you can see the job each one does for integrity. One keyword is new. A CHECK constraint is a rule the database tests on every insert and update, such as "the number of days must be from 1 to 30".

SQL · CHECK and FOREIGN KEY in a Loans table
CREATE TABLE Loans
(
    LoanId    INT IDENTITY(1,1) PRIMARY KEY,                -- entity integrity
    BookId    INT  NOT NULL FOREIGN KEY REFERENCES Books(BookId),   -- referential
    LoanDate  DATE NOT NULL,                                -- domain
    DaysAllowed INT NOT NULL CHECK (DaysAllowed BETWEEN 1 AND 30)   -- domain
);

With this table, SQL Server refuses a loan for BookId 99 if no book 99 exists. It also refuses to delete a book that still has loans. And it refuses a loan of 45 days.

SQL injection

SQL injection
An attack where a user types SQL code into an input box, and the app pastes it straight into its own SQL. The database then runs the attacker's code as part of the command.
ExampleA login form that joins the username into its SQL can be fooled into logging someone in without a password.
ExampleA search box that joins its text into SQL can be used to read, or even delete, a whole table.

Here is how it works. Look at this unsafe search code.

C# · UNSAFE, never do this
string sql = "SELECT * FROM Students WHERE Name = '" + nameTextBox.Text + "'";

A normal user types Sipho, and the SQL is fine. An attacker types ' OR 1=1 -- instead. Now the SQL becomes this.

SELECT * FROM Students WHERE Name = '' OR 1=1 --'

The condition 1=1 is always true, so every student comes back. The -- turns the rest of the line into a comment. The attacker has changed your command. With a parameter, the same text is treated as an odd name to search for, and nothing comes back.

C# · SAFE, use a parameter

C# · ValidateNewItem in Form1.cs
// Runs every check that does NOT need the database.
// Returns true only if ALL checks pass.
// The out parameters hand the clean values back to the caller.
private bool ValidateNewItem(out string itemName, out decimal price, out int quantity)
{
    itemName = itemNameTextBox.Text.Trim();
    price = 0m;
    quantity = 0;

    // 1. Presence check. Spaces only counts as empty.
    if (string.IsNullOrWhiteSpace(itemName))
    {
        ShowError("Please enter an item name.", itemNameTextBox);
        return false;
    }

    // 2. Length check.
    if (itemName.Length > MaxNameLength)
    {
        ShowError("The item name can have at most " + MaxNameLength + " characters.", itemNameTextBox);
        return false;
    }

    // 3. Type check for price.
    if (!decimal.TryParse(priceTextBox.Text, out price))
    {
        ShowError("The price must be a number, for example 12.99.", priceTextBox);
        return false;
    }

    // 4. Range check for price.
    if (price <= 0 || price > MaxPrice)
    {
        ShowError("The price must be more than R0 and at most R" + MaxPrice + ".", priceTextBox);
        return false;
    }

    // 5. Type check for quantity.
    if (!int.TryParse(quantityTextBox.Text, out quantity))
    {
        ShowError("The quantity must be a whole number.", quantityTextBox);
        return false;
    }

    // 6. Range check for quantity. Zero is allowed, it means sold out.
    if (quantity < 0 || quantity > MaxQuantity)
    {
        ShowError("The quantity must be from 0 to " + MaxQuantity + ".", quantityTextBox);
        return false;
    }

    return true;
}

Look at the method header. The word out marks an out parameter (a parameter the method fills in and hands back to the code that called it). A method can only return one value. Here it returns true or false, and uses three out parameters to hand back the clean name, price and quantity as well. You used the same idea every time you wrote int.TryParse(text, out number).

Why Software Testing Matters

New Addition

Why do we test software at all, if the code already compiles and runs? Because compiling only proves the grammar is right. It says nothing about whether the program does the right thing. The tuck shop app compiled perfectly even before you added validation, and it still accepted a blank item name.

Software testing
Running a program with planned inputs and comparing what it actually does with what it should do, in order to find defects.
ExampleYou type a price of 0 into the tuck shop app, expecting a rejection. If the app accepts it, testing has found a defect.
ExampleBefore a bank releases a new app version, testers transfer money between test accounts to check that the balances add up.

Error, defect and failure

These three words sound alike, but they describe three different stages of the same problem.

TermWhat it isExample
ErrorA human mistake made by the developerThe developer types < where they meant <=
Defect, also called a bugThe wrong code that the mistake leaves in the programThe line if (price < 0) lets a price of 0 through
FailureWhat the user sees when the defect runsAn item is saved with a price of R0.00

Why it matters

  • Defects cost more the later you find them. A defect found while coding takes minutes to fix. The same defect found after users rely on the system can mean wrong data in hundreds of records.
  • Testing protects users and data. It is the last line of defence for everything you built in Part 3.
  • Testing can show that defects exist, but it can never prove there are none. You cannot try every possible input. That is why you choose test data carefully, as you will see shortly.
Testing Is Not the Same as Debugging

Testing finds that something is wrong. Debugging finds out why, and fixes it. You test first, then debug with tools such as breakpoints and stepping through code, then test again.

Step 3 · Add the abstract base class

Add a class file called DataAccessBase.cs. Add the using directive at the top and replace the empty class.

C# · DataAccessBase.cs
using Microsoft.Data.SqlClient;

// abstract: nobody creates a plain DataAccessBase object.
// It exists only to share code with the data tier classes.
internal abstract class DataAccessBase
{
    // The ONE place the connection string lives.
    private const string ConnectionString =
        @"Server=(localdb)\MSSQLLocalDB;Database=TuckShopDB;" +
        "Integrated Security=True;TrustServerCertificate=True;";

    // protected: the derived classes can call this, but forms cannot.
    protected SqlConnection CreateConnection()
    {
        return new SqlConnection(ConnectionString);
    }
}

Notice two things. This abstract class has no abstract methods, and that is allowed. It is abstract only because a plain DataAccessBase object would be useless. And here is the protected modifier from Part 1 doing real work. Forms cannot open connections directly, but every data tier class can.

Step 4 · Add the UserData class

C# · UserData.cs
using Microsoft.Data.SqlClient;

// UserData is a DataAccessBase, so it inherits CreateConnection().
internal class UserData : DataAccessBase
{
    // Returns true only if exactly one user matches BOTH values.
    public bool IsValidLogin(string username, string password)
    {
        string sql = "SELECT COUNT(*) FROM Users " +
                     "WHERE Username = @username AND Password = @password";

        using (SqlConnection connection = CreateConnection())
        using (SqlCommand command = new SqlCommand(sql, connection))
        {
            // Parameters stop a user from typing SQL into the login boxes.
            command.Parameters.AddWithValue("@username", username);
            command.Parameters.AddWithValue("@password", password);

            connection.Open();
            int matches = (int)command.ExecuteScalar();
            return matches == 1;
        }
    }
}

Step 5 · Add the StockData class

This class has one method for each letter of CRUD, plus one uniqueness check.

C# · StockData.cs
using System.Data;
using Microsoft.Data.SqlClient;

internal class StockData : DataAccessBase
{
    // READ. Every item, sorted by name.
    public DataTable GetAllItems()
    {
        DataTable table = new DataTable();
        string sql = "SELECT ItemId, ItemName, Price, Quantity FROM Stock ORDER BY ItemName";

        using (SqlConnection connection = CreateConnection())
        using (SqlDataAdapter adapter = new SqlDataAdapter(sql, connection))
        {
            adapter.Fill(table);
        }
        return table;
    }

    // CREATE. Adds one new item.
    public int AddItem(string itemName, decimal price, int quantity)
    {
        string sql = "INSERT INTO Stock (ItemName, Price, Quantity) " +
                     "VALUES (@name, @price, @quantity)";

        using (SqlConnection connection = CreateConnection())
        using (SqlCommand command = new SqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@name", itemName);
            command.Parameters.AddWithValue("@price", price);
            command.Parameters.AddWithValue("@quantity", quantity);
            connection.Open();
            return command.ExecuteNonQuery();   // number of rows added
        }
    }

    // UPDATE. Changes the item with this ItemId only.
    public int UpdateItem(int itemId, string itemName, decimal price, int quantity)
    {
        string sql = "UPDATE Stock SET ItemName = @name, Price = @price, " +
                     "Quantity = @quantity WHERE ItemId = @id";

        using (SqlConnection connection = CreateConnection())
        using (SqlCommand command = new SqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@name", itemName);
            command.Parameters.AddWithValue("@price", price);
            command.Parameters.AddWithValue("@quantity", quantity);
            command.Parameters.AddWithValue("@id", itemId);
            connection.Open();
            return command.ExecuteNonQuery();
        }
    }

    // DELETE. Removes the item with this ItemId only.
    public int DeleteItem(int itemId)
    {
        string sql = "DELETE FROM Stock WHERE ItemId = @id";

        using (SqlConnection connection = CreateConnection())
        using (SqlCommand command = new SqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@id", itemId);
            connection.Open();
            return command.ExecuteNonQuery();
        }
    }

    // Uniqueness check. Is this name used by any OTHER item?
    // When adding, pass 0 as the id, because no real item has ItemId 0.
    public bool NameTakenByAnotherItem(string itemName, int currentItemId)
    {
        string sql = "SELECT COUNT(*) FROM Stock " +
                     "WHERE ItemName = @name AND ItemId <> @id";

        using (SqlConnection connection = CreateConnection())
        using (SqlCommand command = new SqlCommand(sql, connection))
        {
            command.Parameters.AddWithValue("@name", itemName);
            command.Parameters.AddWithValue("@id", currentItemId);
            connection.Open();
            return (int)command.ExecuteScalar() > 0;
        }
    }
}

Look at the WHERE in UpdateItem and DeleteItem. Both use the primary key, so each call changes exactly one row. That is the "never forget the WHERE" rule from Part 2, built into the code.

C# · LoginForm.cs
using Microsoft.Data.SqlClient;

public partial class LoginForm : Form
{
    private const int MaxAttempts = 3;
    private UserData userData = new UserData();
    private int failedAttempts = 0;

    // Program.cs reads this after a successful login.
    // private set: any class can READ it, but only LoginForm can CHANGE it.
    public string LoggedInUser { get; private set; } = "";

    public LoginForm()
    {
        InitializeComponent();
    }

    private void loginButton_Click(object sender, EventArgs e)
    {
        string username = usernameTextBox.Text.Trim();
        string password = passwordTextBox.Text;

        // Presence check on both boxes.
        if (username == "" || password == "")
        {
            MessageBox.Show("Please enter both your username and your password.");
            usernameTextBox.Focus();
            return;
        }

        try
        {
            if (userData.IsValidLogin(username, password))
            {
                LoggedInUser = username;
                // Closes this form and tells Program.cs the login worked.
                this.DialogResult = DialogResult.OK;
            }
            else
            {
                failedAttempts++;   // ++ adds 1 to the variable

                if (failedAttempts >= MaxAttempts)
                {
                    MessageBox.Show("Too many failed attempts. The application will close.");
                    this.DialogResult = DialogResult.Cancel;
                }
                else
                {
                    MessageBox.Show("Incorrect username or password. " +
                                    (MaxAttempts - failedAttempts) + " attempt(s) left.");
                    passwordTextBox.Clear();
                    passwordTextBox.Focus();
                }
            }
        }
        catch (SqlException ex)
        {
            MessageBox.Show("Could not reach the database. " + ex.Message);
        }
    }

    private void cancelButton_Click(object sender, EventArgs e)
    {
        this.DialogResult = DialogResult.Cancel;
    }
}

Notice the message for a failed login. It never says whether the username or the password was wrong. If it did, an attacker would learn which usernames exist. Vague on purpose is good security.

public partial class StockForm : Form

    {

    // The same six checks you wrote in Part 3.
    private bool ValidateItem(out string itemName, out decimal price, out int quantity)
    {
        itemName = itemNameTextBox.Text.Trim();
        price = 0m;
        quantity = 0;

        if (string.IsNullOrWhiteSpace(itemName))
        {
            ShowError("Please enter an item name.", itemNameTextBox);
            return false;

            return false;

            return false;

            ShowError("The price must be more than R0 and at most R" + MaxPrice + ".", priceTextBox);
            return false;
        }
        if (!int.TryParse(quantityTextBox.Text, out quantity))
        {
            ShowError("The quantity must be a whole number.", quantityTextBox);
            return false;
        }
        if (quantity < 0 || quantity > MaxQuantity)
        {
            ShowError("The quantity must be from 0 to " + MaxQuantity + ".", quantityTextBox);
            return false;
        }
        return true;
    }
}

Reading the new code

  • The constructor has a parameter. StockForm(string username) means the form cannot open without a username. That is how the login form's answer reaches the main form.
  • selectedItemId remembers the clicked row. CellClick stores the ItemId. Update and Delete use it in their WHERE clause, and refuse to run while it is 0.
  • e.RowIndex is the number of the clicked row. It is -1 when the user clicks a column heading, which is why the method checks for it.
  • Convert.ToInt32(...) turns the cell's value, which arrives as an object, into an int.
  • MessageBox.Show can ask a question. With MessageBoxButtons.YesNo it shows Yes and No buttons, and returns a DialogResult that says which one was clicked.
The First Row May Look Selected

When the form opens, the grid may highlight the first row by itself. Nothing is really selected until the user clicks a row, because selectedItemId is still 0. Update and Delete will ask the user to click an item first.

Wrapping Up

Summary and Final Checklist

New Addition

You have reached the end of the guide. So what should you take away from it all? Here are the key ideas, part by part.

What you now understand

  • Classes and access modifiers. Public members are for other code to use. Private members belong to the class alone. Internal limits a class to your project, and protected opens a member to derived classes only.
  • Inheritance. A derived class reuses a base class and adds only what is new. Use it only when the is-a test is true. The base constructor runs first, and : base(...) passes values up to it.
  • Polymorphism. A base variable can hold a derived object. With virtual and override, the object decides which version runs. Abstract classes cannot be created, and their abstract methods must be overridden.
  • Databases. A database keeps data after the app closes. Data lives in tables of rows and columns. The primary key makes each row unique, and a foreign key links rows across tables.
  • SQL and CRUD. INSERT creates, SELECT reads, UPDATE changes and DELETE removes. WHERE, LIKE and ORDER BY shape a SELECT, and an UPDATE or DELETE without WHERE touches every row.
  • ADO.NET. Your app talks to the database through a connection, commands and a data adapter. That code lives in a data tier class, never in the form. Parameters keep user input safe.
  • System integrity. A trustworthy system is robust, validates its input, protects its data and is easy to maintain. Validation handles the predictable problems. try and catch handles the rest.
  • Testing. Test cases with exact expected results, chosen with normal, boundary and erroneous data, find defects. A defect log makes sure each defect is fixed, retested and regression tested.
  • Putting it together. A login form opened with ShowDialog hands its answer back through DialogResult. The main form then runs each CRUD operation through a data tier class, with validation first and try and catch around every database call.
